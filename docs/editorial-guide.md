# 爆速AI NEWS 編集ガイド

爆速AI会員向けニュースサイトの記事を書くときのルールです。Claudeが下書きを作るときも、人が書くときも、このガイドに従ってください。

## 1. 読者（爆速AI会員）

| ペルソナ | 特徴 | 知りたいこと |
|---|---|---|
| 経営者・管理職（40〜50代） | 部下に「AIを使え」と言うが、自分は使いこなせていない | 会社に入れる価値があるか、何から始めるか |
| 事務・総務・経理（30〜40代） | Excelやルーチン業務を楽にしたい | 明日の仕事でそのまま使える手順 |
| マーケ・営業（30〜40代） | 競合より早く新しいツールを使いたい | 新機能・新ツール、提案書や分析への使い方 |

爆速AIのゴールは「**AIで月10時間の作業時間を減らすこと**」です。すべての記事は、この目標に役立つかどうかで判断します。

## 2. 記事にするネタの選び方

**選ぶもの**（優先度が高い順）

1. ChatGPT・Gemini・Claude・Copilot・NotebookLM など、会員がすでに使っているツールの**仕事に効く新機能**
2. 次の業務カテゴリが楽になるもの：メール返信／文章作成／校正／要約／データ分析／議事録／録音の文字起こし／画像の文字起こし／スライド作成／Excel
3. AIを仕事で使うときの注意点（情報漏えい、著作権、ハルシネーション、社内ルール）
4. 中小企業が使える、無料または安い新ツール

**選ばないもの**

- 開発者・エンジニア向けの話（API料金、ベンチマークの点数、モデルの仕組みなど）
- 資金調達・株価・企業買収など、会員の仕事に直接関係しないビジネスニュース
- 噂・リーク・未発表の情報
- 一次情報（公式発表）か信頼できる報道で確認できないもの

## 3. 記事の種類（category）の定義

サイトのカテゴリは次の5つ。**どのカテゴリに入れるか迷ったら、この表の「入れるもの」で判断する。**

| カテゴリ | 入れるもの（定義） | 入れないもの | 更新頻度 | 必須項目 |
|---|---|---|---|---|
| `weekly` 今週のTop | 1週間分をまとめたランキング。「おすすめYouTube Top5」と「仕事に役立つAI情報 Top10」の2本 | 単発のニュース | 毎週月曜に2本 | `ranking:`（5件・10件） |
| `news` ニュース | **事実の速報**。AIツールの新機能・新サービス、料金や規約の変更、企業・自治体の活用事例。1記事1ニュース | 使い方の手順解説（→howto）、動画紹介（→video） | 毎朝2本 | 元記事カード（`sources` 1件目）、`impact` |
| `video` おすすめ動画 | **ペルソナ（立場）ごとに選んだYouTube動画1本の紹介**。その立場の人が業務10カテゴリのどれに使えるかを明記。加えて、仕事以外でも毎日使える **「AIで自分磨き」** 枠の動画（下記） | 動画のまとめランキング（→weekly） | 週4本（月・火・木・土） | `youtube:`、`audience:`（1つ）、`task:`。自分磨き枠は `skillup:` |
| `howto` 使い方・特集 | **業務10カテゴリごとの実践ガイド**。手順・図解・画面イメージで「明日やり方が分かる」記事。講座の内容を最新ツールでやり直す記事も含む | ニュースそのもの | 週2本（水・日） | `task:`、手順、図解 |
| `prompt` プロンプト（一覧は「使い方・プロンプト」） | **コピーしてすぐ使えるプロンプト**と、使う場面・コツ | 長い解説（→howto） | 週1本（金） | コードブロックのプロンプト、`task:` |

### ペルソナ（`audience:`）

`経営者・管理職` ／ `事務・総務・経理` ／ `マーケ・営業` の3つ（スプレッドシート「ペルソナ」・営業資料_V04より）。

- 経営者・管理職（40〜50代）：AIを会社に導入したいが、何から始めればいいか分からない。部下に「AIを使え」と言うが自分は使いこなせていない
- 事務・総務・経理（30〜40代）：Excelやルーチン業務をAIで効率化したい。具体的なやり方が知りたい
- マーケ・営業（30〜40代）：資料作成やデータ分析をAIで速くしたい。最新ツールで差をつけたい

### 業務カテゴリ（`task:`）

爆速AI 業務効率化コースの10カテゴリから1つ選ぶ（営業資料_V04のカリキュラム構成より）：
`メール返信`／`文章作成`／`文章の要約`／`文章の校正・添削`／`会議資料のデータ分析`／`議事録作成`／`録音の文字起こし`／`画像の文字起こし`／`プレゼン資料作成`／`Excel活用`

- 業務別ページ（`/tasks/…`）には、`task:` が一致する記事に加えて、業務ごとに決めたキーワード（`lib/categories.ts` の `TASK_LIST` の `tags`。例：議事録作成 → `議事録`）を持つ記事も並ぶ。タグはこの表記に合わせる

### むずかしさ（`level:`）

すべての記事（`weekly` を除く）に、次の3段階から1つ付ける。一覧のカードと記事ページに印（棒3本）で表示され、一覧の「むずかしさ」ボタンで絞り込める。

| level | 対象の読者 | 目安 |
|---|---|---|
| `初級` | AIをほとんど使ったことがない人 | ボタン操作・コピペだけでできる。新機能のニュースで、設定なしで使えるもの |
| `中級` | ふだんAIを使っている人 | ファイルの読み込み、条件の指定、追い質問、複数の機能の組み合わせ、設定や有料プランが必要なもの |
| `上級` | AIを仕組みとして使いたい人 | 専用AIの作成、複数ステップの設計、評価基準づくり、チームへの展開・社内ルールまで |

- 迷ったら低いほうに付ける。上級ばかりにならないよう、週に1本程度を目安にする
- `level` の書き間違いは `npm run build` でエラーになる

### 「AIで自分磨き」枠（`skillup:`）

ペルソナを問わず、**仕事以外でも毎日使えるAI活用**の動画を紹介する枠。おすすめ動画ページでは、ペルソナ別の枠の下に「AIで自分磨き」としてまとめて表示される。

- `skillup:` にテーマを1つ書く：`英語・語学`／`調べもの・情報収集`／`学び直し・資格`／`アイデア出し・壁打ち`／`暮らし・健康`
- 例：ChatGPTで英会話の練習、ChatGPTの音声会話モードで調べもの、AIで資格の勉強、旅行や献立の計画
- `audience:` は3つのペルソナすべて、`task:` は省略してよい
- 記事タイトルは「【AIで自分磨き】＋動画で分かること」の形にする
- 最近扱っていないテーマを優先する

### おすすめ動画の書き方

- **載せる動画の基準（すべて満たすものだけ）**。候補ごとに `bash scripts/youtube-check.sh <動画IDかURL>` を実行し、「判定: OK」の動画だけを使う。NG・確認できない動画は載せない
  - 公開から7日以内（記事の公開日基準）
  - 長さ5分以上（ショート動画・30秒ほどの予告動画は対象外。実例や手順が入らないため）
  - 再生1,000回以上・高評価20以上・コメント3件以上（ある程度見られ、反応がある動画）
  - 説明文（スクリプトが先頭を表示する）に、実演・事例・手順・チャプターなど具体的な中身があること。宣伝や告知だけの動画は載せない
  - 判定には YouTube Data API のキー（環境変数 `YOUTUBE_API_KEY`）が必要。キーが無いときは動画記事を作らず、その旨を報告する
- 条件に合う動画が無い日は、無理に載せない（動画記事を作らずに報告する）。「この動画について」の表には、公開日・長さ・再生回数を書く
- 新しい動画は、検索結果から探すほか、信頼できるチャンネルのRSS（`https://www.youtube.com/feeds/videos.xml?channel_id=UC...`）で最新動画を見ると見つけやすい
- YouTubeで探した動画は、**動画ページ（またはYouTubeの oEmbed：`https://www.youtube.com/oembed?url=動画URL&format=json`）でタイトルとチャンネル名を確認**してから載せる。確認できない動画は載せない
- 記事タイトルは「【〇〇向け】＋動画で分かること」の形にする
- 本文は「この動画について（表）」「この動画で分かること」「見るときのポイント」「見たあとにやること」の順。見たあとにやることでは、このサイトの関連記事・プロンプト・レクティの講座につなげる
- Claudeは動画を再生できないので、内容はタイトル・説明文・公開情報の範囲で書き、その旨の注記を入れる
- `sources` には動画を、`media` は「YouTube／チャンネル名」で書く

## 4. 書き方のルール

- **専門用語は使わないか、使うなら一言で説明する**（例：「ハルシネーション（AIがもっともらしいウソを書くこと）」）
- **1文は短く**。「です・ます」調で書く
- 見出しは「何が変わったの？」「誰が使えるの？」「使い方」「気をつけること」のように、読者の疑問の形にする
- 手順は番号付きリストで、1ステップに1つの操作
- **ニュース記事には必ず `impact` を書く**。記事の下に「COLUMN 爆速AIからのひとこと」として出る、編集部のコラム（2〜4文）。「どの業務の、何分が、どう変わるか」「まず何から試すか」を、会員に語りかける口調で具体的に書く。レクティの講座への誘導は書かない（記事の最後には公式LINEへの質問案内が自動で出る）
- 日付は「2026年10月6日」のように年から書く
- 確認できなかったことは書かない。報道ベースの情報は「〜と報じられています」と書く
- 「」や（）で始まる・終わる部分を太字にするときは、`**「〇〇」**` ではなく `<strong>「〇〇」</strong>` と書く（Markdownの仕様で `**` が太字にならないため）

## 5. 図解

記事1本につき最低1つの図解を入れます。図解はMarkdownの中にインラインSVGで書きます。

```html
<figure class="diagram">
<svg viewBox="0 0 720 200" role="img" aria-label="図の説明">
<rect x="16" y="20" width="200" height="80" rx="10" class="d-box"/>
<text x="116" y="66" text-anchor="middle" class="d-text" font-size="28">見出し</text>
</svg>
<figcaption>図：キャプション</figcaption>
</figure>
```

- 使えるクラス：`d-box`（通常の箱）、`d-accent`（強調の箱）、`d-text`（太字の文字）、`d-sub`（小さい補足）、`d-arrow`（矢印の線）、`d-arrowhead`（矢じり）
- 色は直接指定しない（クラスを使えば、ダークモードでも自動で見やすい色になる）
- **SVGの中に空行を入れない**（Markdownが壊れるため）
- 矢印の `marker` の `id` は記事内で重複しないようにする（例：`ah1`、`ah2`）
- 横幅は `viewBox="0 0 720 …"` を基本にし、**文字は26以上**で書く（`<text>` に `font-size="28"` のように付ける。付けないと小さい既定の大きさになる）（スマホでは図が約半分に縮むため、26でスマホ約13pxになる）。横に3つ以上並べる図は、スマホでも読めるよう縦に積む配置を優先する

## 6. スクリーンショット

- 画像は `public/images/articles/<記事のファイル名>/` に保存し、記事では `/images/articles/<記事のファイル名>/xxx.png` で参照する
- 画像には `<figure>` と `<figcaption>` を付ける
- 実際の画面のスクショがない場合は、まず**画面イメージ図**（SVGで描いた簡略化した画面に、赤枠と番号で操作場所を示す図）を入れる。クラス `d-screen`（画面の背景）、`d-mark`（赤枠）、`d-mark-dot`＋`d-mark-num`（番号の丸）を使う。キャプションには必ず「画面イメージ」「実際の画面と異なる場合があります」と書く
- 編集部から実際のスクショが届いたら、Claudeが赤枠・番号を書き込んでから記事に入れる（個人情報はぼかす）
- 画面イメージ図も作れない場合は、撮影してほしい画面を説明した**差し込み枠**を置く：

```html
<div class="shot-placeholder">📷 スクショ差し込み枠：〇〇の画面<br>（編集部で撮影して <code>/images/articles/…/xxx.png</code> に保存）</div>
```

- 編集部がスクショを撮ったら、差し込み枠を次のように置き換える：

```html
<figure><img src="/images/articles/…/xxx.png" alt="〇〇の画面"><figcaption>〇〇の画面</figcaption></figure>
```

- 個人名・メールアドレス・社内情報が写っている部分は、必ずぼかしてから保存する

## 7. 出典

- `sources:` には、記事の根拠にしたページを必ず入れる。できるだけ**公式発表（一次情報）**を最初に書く
- 出典にないことを事実として書かない

## 8. ファイルの作り方

- ファイル名：`content/articles/YYYY-MM-DD-英語のスラッグ.md`（例：`2026-10-07-chatgpt-audio-upload.md`）
- テンプレート：`content/articles/_template.md` をコピーして使う
- `pickup: true` を付けると、トップページの一番大きい枠に表示される（その日いちばん大事な記事1本だけに付ける）
- `thumbLabel:` はサムネイルに大きく表示される短い文字（12文字前後）

## 9. 今週のTop（毎週1回）

毎週、次の2本を `category: weekly` で公開する。ランキングは frontmatter の `ranking:` に書く（上から1位、2位…の順）。

| 記事 | 本数 | 選び方 |
|---|---|---|
| 今週のおすすめYouTube Top5 | 5本 | 会員が明日の仕事で使えるテーマの解説・実演動画。**「おすすめ動画の書き方」の基準をすべて満たす動画だけ**（`scripts/youtube-check.sh` で「判定: OK」のもの）。初心者向け1本以上、事務職向け1本以上を入れる |
| 今週の「仕事に役立つAI情報」Top10 | 10本 | その週のニュース・新機能・解説記事。このサイトの記事があれば優先して入れる（`url: "/articles/..."`） |

```yaml
ranking:
  - title: "動画・記事のタイトル（元のタイトルのまま）"
    url: "https://www.youtube.com/watch?v=XXXX"
    youtube: "XXXX"       # YouTubeのときだけ。サムネイルが表示される
    channel: "チャンネル名や媒体名"  # 分からなければ省略
    comment: "編集部のおすすめポイント（2〜3文）。誰に・なぜおすすめか"
```

- タイトルは元のタイトルをそのまま書く（言い換えない）
- **Claudeは動画を再生して中身を確認できない**。`comment` はタイトル・説明文・検索結果から分かる範囲で書き、見ていない内容（「◯分ごろに〜」など）は書かない。公開前に編集部が動画を確認する
- 同じ動画・記事を2週続けて載せない
- ファイル名の例：`2026-10-07-weekly-youtube-top5.md`、`2026-10-07-weekly-info-top10.md`。タイトルの最後に「（10月第2週）」のように週を書く

## 10. アイキャッチ画像（必須）

画像の無い記事は読まれないので、すべての記事にアイキャッチを付ける。基本は自動で決まる（上から順に、見つかったものを使う）。

1. `thumbnail:` — 自前で用意した画像（最優先）
2. `youtube:`、またはランキング1位のYouTube動画のサムネイル
3. `eyecatchFrom:` または `sources` 1件目のページのOGP画像（ニュースサイトや公式ブログがSNS共有用に用意している画像）
4. どれも無ければ、`thumbLabel` を大きく入れたオリジナル画像を自動生成（カテゴリ色の光と方眼の背景。記事タイトルは画像に入れない）（`/eyecatch/<スラッグ>.png`）

- **ニュース記事は、公式発表やニュース記事を `sources` の1件目に置く**（そのページの画像がアイキャッチになる）
- **すべての記事に、目を引く `thumbLabel`（12文字前後のキャッチコピー）を書く**。自動生成のアイキャッチに1行で大きく表示される。16文字以内が目安（長いと文字が小さくなる）（例：「録音ファイル → 議事録」「AIのウソを見抜く3チェック」）
- 素材サイトの写真（Unsplash・Pexelsなど）を自動で検索して載せることはしない（各サービスの規約で、自動での利用が認められていないため）
- ランキングの各項目にも、YouTubeサムネ・記事のアイキャッチ・リンク先のOGP画像が自動で付く
- 外部サイトの画像には「画像：〇〇」と出典が自動で表示される

## 11. AI NEWS FEED（自動）

トップページの「AI NEWS FEED」は、`lib/feeds.ts` に登録したニュースサイトのRSSから、AI関連の記事を1時間ごとに自動で集めて表示する。見出し・画像・リンクだけを表示し、本文は元のサイトで読んでもらう（転載はしない）。フィードの追加・削除は `FEEDS` を編集する。

## 12. 元記事の確認と画像の引用（必須）

- **記事にするニュースは、必ず元の記事（できれば公式発表）を WebFetch などで開いて読んでから書く。** 検索結果の要約だけで書かない
- **元の記事を開けなかったニュースは記事にしない**（別のネタに替える）
- アイキャッチは、開いた元記事の `og:image`（SNS共有用の画像）のURLを確認して、次のように書く：

```yaml
thumbnail: "https://（元記事の og:image の画像URL）"
thumbnailCredit: "出典：窓の杜「OpenAI、「DevDay 2026」を開催」"   # 媒体名と記事タイトルを正確に
thumbnailCreditUrl: "https://forest.watch.impress.co.jp/docs/news/2144866.html"  # 元記事のURL
```

- 本文に画像を入れるときも、元記事・公式ブログに実際に載っている画像のURLを使い、すぐ下に出典を書く：

```html
<figure><img src="https://（画像URL）" alt="画像の説明"><figcaption>出典：<a href="https://（元記事URL）">媒体名「記事タイトル」</a></figcaption></figure>
```

- 画像は1記事につき、アイキャッチ＋本文1〜2枚まで。記事の主役は自分たちの解説文・図解にする（引用は補足）
- 「転載禁止」と書かれている画像、人物写真、他社の有料素材は使わない。迷ったら公式発表（企業のニュースルーム・公式ブログ）の画像を使う

### 元記事カード（NewsPicks風）

ニュース記事（`category: news`）では、`sources` の1件目が記事の上部に「元記事カード」（元記事の画像・タイトル・媒体名）として大きく表示される。

- `sources` の1件目には、いちばん中心になる元記事（できれば公式発表）を置く
- `title` は元記事のタイトルを正確に、`media` に媒体名を書く。`image` に元記事の og:image を書くと確実に表示される（省略時は自動取得）
- 元記事の本文はコピーしない。引用するときは「」で囲んだ短い一文にとどめ、出典を明記する。記事の中心は編集部の解説にする

```yaml
sources:
  - title: "OpenAI、「DevDay 2026」を開催 ～常時稼働エージェント「dots」や「ChatGPT Space」などを発表"
```

## 13. 定期実行（自動で記事を書く）

| いつ | 何を書く |
|---|---|
| 毎朝7時（6時59分に開始） | ニュース2本＋曜日ごとの1本（3章「曜日ごとの更新スケジュール」） |
| 毎週月曜の朝（6時28分に開始） | 「今週のTop」：おすすめYouTube Top5 と、仕事に役立つAI情報 Top10 |

手順：
1. `content/articles/` の既存記事を見て、同じネタを重複して書かない
2. WebSearch でネタを探し、元記事を開いて内容と画像を確認する
3. このガイドに従って記事を書く（図解・爆速AIからのひとこと・出典・画像の引用元）
4. `npm run build` が通ることを確認してからコミットし、本番ブランチに push する

## 14. 過去の記事の扱い（バックナンバー）

- 記事は削除しない。新しい記事が増えると、トップページから順に押し出される
- カテゴリページは新しい順に24本ずつ表示し、古い記事は「過去の記事 →」で2ページ目以降へ
- `/archive`（バックナンバー）で月ごとに全記事を探せる
- 公開から180日たった記事には「この記事は約○か月前の情報です」という注意書きが自動で出る
- ビルド時に作るのは直近120日分の記事ページとアイキャッチ画像だけ。それより古いものは最初に読まれたときに作って保存する（記事が増えても公開作業が重くならないように）
- 設定値は `lib/articles.ts` の `PAGE_SIZE`・`STALE_DAYS`・`PREBUILD_DAYS`
